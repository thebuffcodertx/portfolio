## Git Branching Strategy

This repository follows a three-environment branching strategy:

| Branch | Purpose |
|---|---|
| `prod` | Production-ready code deployed to the live website |
| `stage` | Pre-production validation and testing |
| `dev` | Integration of new features and ongoing development |
| `feature/*` | Individual features developed in isolated branches |

### Development Workflow

1. Create a feature branch from `dev`.
2. Implement and test the feature.
3. Open a pull request targeting `dev`.
4. Promote validated changes from `dev` to `stage`.
5. Merge approved changes from `stage` into `prod`.
